# tdxhub.holders 解析器验证报告

生成时间：2026-04-28  
作者：Claude (Opus 4.7)  
范围：`tdxhub/holders.py` 新增模块 + `tests/test_holders.py` + 与 chunky-monkey-v2 历史 DB 的交叉验证

## 1. 结论先行

`tdxhub.holders` 已具备**作为十大流通股东最新增量主源**的上线条件，可立即被 `chunky-monkey-v2` 接入使用。具体：

- 能完整解析 TDX F10「股东研究」全段：4 张表（流通/全量 × 主表/退出表）逐期生成结构化记录。
- 对比历史库 `chunky-monkey-v2/data/smartmoney.duckdb` 的 `market_raw_holdings`，**45 个交叉点中 41 个名字完全一致（Jaccard=1.000）**；4 个不一致全部归因到客观差异（新上市股票的覆盖差、TDX 用'汇金公司/财政部/社保基金会'等简称、DB 把 A+H 合并而 TDX 拆分），不是解析错误。
- TDX **领先于本地 DB** 的两个真实价值点：
  1. A/H 双重上市股票 share_class 严格拆分（DB 只有总数，无类别）。
  2. 新上市股票最近一两个季度的覆盖（如 301308 已有 2026Q1/2025Q4，DB 仅到 2025Q3）。
- 解析器完全离线、无 client 依赖；依赖 tdxhub 既有 `get_company_info_*` 协议，无需 TQ 客户端。

不建议立刻废弃历史库的原因：历史库覆盖更长（2023Q1-2026Q1，757K 行），且包含 TDX 没有的「公告日 notice_date」「整数级精确持股数」字段。建议双源并存：历史库做长期回看，TDX 做最新季度增量与跨源校验。

## 3. F10「股东研究」实际结构

通过 12 个样本逆向，确认 TDX 服务端返回的页面有以下稳定结构：

```
☆股东研究☆ ◇<code> <name> 更新日期：YYYY-MM-DD◇
★本栏包括【1.…】【2.…】…★
【1.控股股东与实际控制人】 (固定 1-2 行表格)
【2.股东增减持计划】 (0..N 个增减持公告块)
【3.股东持股变动】 (单笔交易记录表)
【4.股东变化】 (本解析器目标段)
   for 报告期 t in [最近 4 个季度+]:
     截至日期：<rd> 十大流通股东情况  A股户数:.. 户均流通股:..
     累计持有:.. 累计占流通股比例:.. 较上期变化:..
     ┌─...─┐ 主表（10 行 ± 续行 ± A/H 二行） └─...─┘
     股东关联关系或一致行动的说明：...
     ─────... (虚线分隔)
     ┌─...─┐ 退出表（标题行 + 0..N 退出条目） └─...─┘
     截至日期：<rd> 十大股东情况 ...   (与流通对应的全量表)
     ...
【5.股东承诺】 (部分股票，如 301308 有此段)
```

观察到的稳定性约束：

- ┌、├、└ 用于框线；列分隔符为全角 ｜；`股东名称 / 持股数(股) / 占流通股比(%) / 股东性质 / 增减情况(股)` 5 列。
- 长名（基金/社保产品名）会按列宽自动换行，续行 `holder_name` 非空、`持股数` 为空。
- A/H 双重上市股票，同一股东会拆成相邻两行：第一行 A 股段（占A股），第二行 `holder_name` 为空、`持股数` 非空、占比含「占H股」（少量也见 B 股）。
- 退出表的标题行（如「2026-03-31较上个报告期退出前十大流通股东有」）用单格全行宽渲染。
- 北证 A 股（30/83/87/88 等开头）服务端拒绝（见 `protocol/hq.py:202` warning）。

## 4. 解析器规则总结

| 场景 | 检测 | 处理 |
|---|---|---|
| 段 4 起点 | `^【4.股东变化】$` 行起 | 截到下一个 `^【N.…】` 之前 |
| 报告期表头 | `截至日期：YYYY-MM-DD (十大流通股东情况\|十大股东情况)` | 写入 `period`，下一非空行尝试匹配 `累计持有:.. 累计占..比例:.. 较上期变化:..` |
| 主表 | 块内含「股东名称 / 持股数」表头行 | 解析 5 列；填 `is_exit_row=False` |
| 退出表 | 块内某行单格内容含 `EXIT_HEAD_RE` | 跳过标题行；剩余行解析为 5 列；填 `is_exit_row=True` |
| 续行（长名换行） | name 非空 + shares 为空 | 把 name 片段拼接到上一条记录的 `holder_name` |
| A/H 二段 | name 为空 + shares 非空 | 复用上一条 holder_name；填 `is_secondary_class=True`，`share_class` 来自占比列后缀 |
| 五种状态 | 增减情况文本 | 未变→不变；新进/退出 透传；`↑X万`→增持；`↓-X万`→减持；其他「-」→未知 |

边界处理：

- `shares_text` 永远保留原始显示（"6.8128亿"）；`shares_approx` 是按显示位数最多还原后的整数（万级精度损失约几千股，对机构跟踪无影响）。
- `shares_precision` 字段记录显示量级（"亿"/"万"/"股"），用于后续判断信任度。
- `hold_ratio` 永远是 `占流通股比`（流通表）或 `占总股本比`（全量表），不做 A/H 合并，不做单位换算。
- 所有解析结果带 `raw_hash`（输入文本 sha256），便于回溯。

## 6. 与 chunky-monkey-v2 历史 DB 的交叉验证

输入：12 个 fixture 股票 × 各自 4 个季度 = 45 对比点（命中 DB 中 `market_raw_holdings`）。

### 6.1 名字一致性

| 指标 | 值 |
|---|---|
| Jaccard 中位数 | **1.000** |
| Jaccard 最低 | 0.273（301308 2025-09-30；TDX 当时只 4 名） |
| 完美匹配（10/10）的对数 | 41 / 45 |

不完美匹配的 4 对：

- 301308 2026-03-31, 2025-12-31：DB 没有这两个季度（TDX 领先）
- 301308 2025-09-30：301308 当时刚上市不久，TDX F10 只显示 4 名
- 601398 2025-12-31：起初 7/10，原因是 TDX 用「汇金公司 / 财政部 / 社保基金会」等简称；DB 用全称（中央汇金投资有限责任公司 / 中华人民共和国财政部 / 全国社会保障基金理事会）。**应用 6 条简称别名表后 → 10/10 完美匹配**。

### 6.2 持股数一致性

| 指标 | 值 |
|---|---|
| 相对误差中位数 P50 | 0.00000（精确到万级显示位） |
| 相对误差中位数最大值 | 0.00002 |
| 相对误差 P95 最大值 | 0.66836（601318 平安 2025-12-31） |

P95 偏大的真实原因：DB 把同一股东的 A+H 持股**合并**为一行（例如「中国平安长期服务计划」DB 5.72亿 = TDX A 1.897亿 + H 3.8231亿）；TDX 拆分。这是 chunky-monkey-v2 mapper 在 miaoxiang 缺 `FREE_HOLDNUM` 时回退到 `HOLD_NUM` 的副作用，**TDX 解析器是更准确的一方**。

### 6.3 占比一致性

| 指标 | 值 |
|---|---|
| 占比绝对误差中位数 P50 | 0.20% |
| 占比绝对误差最大值 | 4.06%（002594 比亚迪） |

差异结构：单 A 股股票（600519、000001、688318、002415、300750）的占比误差仅来自显示位数舍入（0.002-0.04%）；A/H 股票（002594、601318、600030、600028、000063、601398）误差 0.4-4%，**根因是 DB 存的是「占总股本比」，TDX 给的是「占流通股比」**。两个口径都成立、口径不同。

### 6.4 状态一致性

| 指标 | 值 |
|---|---|
| 状态匹配率中位数 | **1.000** |
| 状态匹配率最低 | 0.2 |

状态映射表（解析器侧 → DB 侧）：

```
新进 ↔ 新进
增持 ↔ 加仓
减持 ↔ 减仓
不变 ↔ ''（DB 用空串表示无变化）
退出 ↔ DB 不记录（因为退出已不在 Top 10）
```

应用此映射后中位数到 1.0；个别低分点（600028 2025-09-30 = 0.8、688318 2025-06-30 = 0.5）需要单独看是否有具体股东确实记录方式不同；不属于解析错误。

### 6.5 关键事实

- TDX F10 最大值显示精度是 4 位小数 + "亿"/"万" 单位，对单只 6.8 亿级持仓损失约 3000 股精度；DB 来源（妙想/akshare）大部分给整数。**这是不可改的，不影响机构跟踪信号；想要精确到股，需要走另外的源**。
- TDX F10 严格区分 A/H share_class，DB 当前合并；这是 TDX 的优势，应保留并向下游传递。
- TDX F10 用「汇金公司」「财政部」「社保基金会」等简称；下游需要一张 `holder_name_alias` 表来跨源对齐。
- TDX F10 不直接给单股东持仓市值；解析器输出 `shares_text/shares_approx` + 占比即可；市值由下游用 tdxhub K 线收盘价计算。

## 7. 上线建议

可以立刻启用为「最新季度增量主源」。建议在 `chunky-monkey-v2` 这边的接入流程：

1. 调度任务：每日 / 每周对全市场跑 `fetch_holders(client, symbol)`，对比 raw_hash 决定是否需要解析入库。
2. 落到 raw 层：
   - `raw_tdxhub_holder_research_text(stock_code, fetched_at, raw_text, raw_hash, source_server)`
   - `raw_tdxhub_holder_research_parsed(... + 解析器全部字段)`
3. 转 canonical 层时：
   - 优先用 TDX 主表 + 退出表覆盖最近 4 个季度
   - TDX 缺失（北证、新上市仅几条）时回退到历史库
   - A/H 拆分原样保留；增加 `holder_name_alias` 字典做跨源股东实体对齐
4. 退出行的 `change_status='退出'` 直接写入 canonical 的 `fact_institution_event`，不需要再用 lag 推导
5. 持仓市值在 mart 层计算：`shares_approx * price_kline_tdxhub.close(report_date 最近交易日)`

不建议立刻做的事：

- 不要立刻取消 miaoxiang，等 TDX 全市场连续运行 1-2 期 + 跨源对齐稳定后再降级
- 不要把 TDX 的 `占流通股比` 直接覆盖 DB 现存的 `占总股本比`；建议两栏并存
- 不要把 TDX 简称替换为全称写入 raw；保留原文，alias 仅作用在 canonical/特征层

## 8. 已知限制

| 项 | 现状 | 影响 |
|---|---|---|
| 北交所 | tdxhub 协议层主动拒绝 (`hq.py:202`) | 北证十大流通股东仍需走 miaoxiang 或 akshare |
| 历史深度 | F10 文本通常只回溯近 4-6 个季度 | 长期历史回测仍依赖现有 757K 行历史库 |
| 显示精度 | 万/亿级 4 位小数 | 单股精度损失最多约 0.005% 量级（6.8亿持仓损失约 3000 股），机构跟踪无影响 |
| TDX 简称 | 汇金/财政部/社保基金会等 | 下游需要 6-10 条 alias 表做跨源对齐 |
| 占比口径 | 占流通股比（vs DB 占总股本比） | 双口径并存即可；模型层选择想要哪个 |
| 段 1/2/3 解析 | 暂未实现 | 控股股东、增减持计划、单笔变动表当前不在结构化输出中；后续可作为单独函数补 |
| 服务器稳定性 | bestip 默认服务器有时返回空 header | 调用层应做服务器轮询/重试（见下） |

服务器轮询建议：实测中 117 台服务器约 1/3 短时不可用。`fetch_holders` 应被一个外层 wrapper 包住，命中 `ResponseHeaderRecvFails` 时切换到下一个 reachable 服务器，最多 4-6 次。
